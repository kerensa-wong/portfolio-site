# Portfolio — Complete Reference Guide

A single-page portfolio site driven entirely by CSV/JSON files and images.
All content updates happen by editing files in `portfolio-data` — no HTML,
CSS, or JS editing required for routine changes.

---

## Architecture

The project uses two repos so your personal data stays private while the live
site is fully public:

| Repo | Visibility | Contains |
|---|---|---|
| `portfolio-data` | **Private** | `data/`, `images/`, `build.js` |
| `portfolio-site` | **Public** (GitHub Pages) | `index.html`, `css/`, `js/` |

### How it stays private

`build.js` reads every CSV, JSON, image, and PDF from `portfolio-data` and
compiles them into a single `data-bundle.js` — all images and PDFs are encoded
as base64 data URIs, all CSVs are pre-parsed into arrays. GitHub Actions pushes
**only this bundle** into `portfolio-site`. No raw CSVs, no raw images, no PDF
files ever appear in the public repo. A visitor inspecting the network tab sees
one JS file, not individual data files.

### Two modes — automatic, no configuration needed

| Mode | When | How data loads |
|---|---|---|
| **Bundled** | GitHub Pages (production) | `data-bundle.js` is present → all data read from `window.__PORTFOLIO_DATA__`, zero fetch calls |
| **Fetch** | Local dev (`npx serve .`) | `data-bundle.js` absent → `fetch()` loads files from local `data/` and `images/` folders |

`main.js` detects which mode it is in automatically. You never need to change
any setting to switch between them.

## One-Time Setup

### 1. Create the two GitHub repos

- Create `portfolio-site` as **Public**
- Create `portfolio-data` as **Private**

### 2. Enable GitHub Pages on `portfolio-site`

Settings → Pages → Source: **Deploy from a branch** → Branch: `main` / `(root)`

Your site will be live at `https://yourname.github.io/portfolio-site/`.

### 3. Create a Personal Access Token (PAT)

The Actions workflow needs write access to `portfolio-site` to push the bundle.

1. GitHub → Settings → Developer Settings → Personal Access Tokens → Fine-grained tokens
2. **Generate new token** — set expiry (1 year recommended)
3. Repository access → select `portfolio-site` only
4. Permissions → Contents: **Read and Write**
5. Copy the token

### 4. Add the token as a secret in `portfolio-data`

`portfolio-data` → Settings → Secrets and variables → Actions → **New repository secret**
- Name: `PAT_PORTFOLIO`
- Value: paste the token

### 5. Set your repo name in the workflow

Edit `.github/workflows/sync-to-site.yml` in `portfolio-data` and replace
`yourname/portfolio-site` with your actual GitHub username and repo name.

### 6. Push both repos

```bash
# portfolio-data (private)
cd portfolio-data
git init && git add . && git commit -m "init"
git remote add origin git@github.com:yourname/portfolio-data.git
git push -u origin main
# ↑ this first push triggers the Actions workflow automatically

# portfolio-site (public)
cd portfolio-site
git init && git add . && git commit -m "init"
git remote add origin git@github.com:yourname/portfolio-site.git
git push -u origin main
```

The workflow runs on the first push to `portfolio-data`, compiles
`data-bundle.js`, and pushes it into `portfolio-site`. GitHub Pages picks
it up within ~1 minute.

## Day-to-Day Workflow

To update content (edit a CSV, replace a photo, update your CV):

```bash
cd portfolio-data
# edit data/profile.csv, replace images/profile.png, etc.
git add . && git commit -m "update: ..." && git push
```

GitHub Actions builds and deploys automatically in ~1 minute. You never touch
`portfolio-site` directly for content updates.

## Local Development

For local preview, clone both repos side by side and symlink the data folders
so changes in `portfolio-data` are reflected instantly without copying:

```bash
# Mac / Linux — symlink (recommended: changes reflect immediately)
ln -s ../portfolio-data/data   portfolio-site/data
ln -s ../portfolio-data/images portfolio-site/images

# Windows — junction (equivalent of symlink)
mklink /J portfolio-site\data   portfolio-data\data
mklink /J portfolio-site\images portfolio-data\images

# Alternative — plain copy (any OS, but you must re-copy after each change)
cp -r portfolio-data/data   portfolio-site/data
cp -r portfolio-data/images portfolio-site/images
```

Then serve locally — `fetch()` requires HTTP, not `file://`:

```bash
cd portfolio-site
npx serve .
# Open http://localhost:3000
```

`data-bundle.js` is absent in this setup, so `main.js` automatically uses
fetch mode. No configuration needed.

### Testing the build locally (optional)

To verify the bundle before pushing:

```bash
cd portfolio-data
node build.js           # writes data-bundle.js to ../portfolio-site/
cd ../portfolio-site
npx serve .             # now runs in bundled mode
```

To go back to fetch mode for local dev, delete `data-bundle.js` from
`portfolio-site/` (it's in `.gitignore` so git won't track it either way).

## Content Reference

### `profile.csv` — Identity, Links, Global Toggles

| key | purpose |
|---|---|
| `name` | Full name |
| `name_suffix` | Optional credentials suffix, e.g. `", CFA, FRM, CAIA"` — must start with `, ` and be quoted. Omit the key or leave blank to hide |
| `title_line1` | Italic role line under your name |
| `title_line2` | Optional second part of title, joined with ` · `. Leave blank to omit the separator dot |
| `tagline` | One-sentence positioning statement |
| `email` | Used by every mailto link sitewide |
| `linkedin` | Used by every LinkedIn button sitewide |
| `cv_file` | Path to CV PDF, e.g. `data/cv.pdf` |
| `location` | Shown in the footer |
| `photo` | Hero photo — PNG or WebP with transparent background |
| `photo_thumb` | Small square crop for the nav avatar |
| `theme` | Default palette: `steel`, `slate`, or `arctic` |
| `show_research` | `true` / `false` — hides the entire Research section |
| `show_hero_stats` | `true` / `false` — hides the hero stat strip and achievement spotlight |
| `hero_bg_photo` | Optional hero background photo |
| `hero_animation` | `particles`, `leaves`, or `none` |

### `stats.csv` — Hero Proof-Point Strip

Three inline stat items displayed between the tagline and action buttons.

```csv
id,value,label
1,US$500bn+,Oversight Capacity
2,8 Years,Asset Owner Experience
3,CFA / FRM / CAIA,Professional Designations
```

- `value` — large display figure (Cormorant Garamond, bold)
- `label` — small muted caption beside it
- Separator rules trail each item so they never appear at the start of a wrapped row
- Toggle visibility via `show_hero_stats` in `profile.csv`

---

### Hero Achievement Spotlight

Fed automatically by `achievements.csv`. Rotates through the first three
achievements every 7 seconds in a card at the base of the hero, showing
`metric_value`, `metric_label`, `title`, and `subtitle`. Clicking navigates
to the full Achievements section.

### `experience.csv` — Timeline

```csv
id,type,period,title,organization,location,description,highlights,logo,external_link
```

- `type` — must be exactly `corporate`, `academic`, or `continuous`
- `highlights` — semicolon-separated bullet points
- `logo` — image path; leave blank to omit for that row
- `external_link` — optional URL shown as "View details ↗"
- The **Professional Development** tab only appears if at least one row has `type=continuous`

### Carousels

All four carousels (Edge, Achievements, Credentials, Gallery) share the same behaviour:

- 3 or fewer items — no arrows or dots
- 4+ items — arrows and dots; advances one full row (3 desktop / 2 tablet / 1 mobile)
- Strict continuity — no item shown twice
- Equal card height within each carousel, measured independently

## CSV Editing Tips

- Wrap any value containing a comma in double quotes: `"CFA, FRM, CAIA"`
- Save from Excel as **CSV UTF-8 (Comma delimited)** — not plain CSV
- Use plain hyphens (`-`) rather than em-dashes (`—`) to be safe
